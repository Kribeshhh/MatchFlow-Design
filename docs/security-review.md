# Phase 12 security review

Reviewed 2026-11-05 against [OWASP ASVS 5.0.0](https://github.com/OWASP/ASVS/releases/tag/v5.0.0) and [OWASP Top 10:2025](https://top10.owasp.org/2025/). This is a repository threat review and automated regression assessment, not independent penetration testing, full ASVS certification, or proof of production configuration. ASVS areas below organize coverage; individual requirements not explicitly exercised remain unverified.

## Assets, actors and trust boundaries

Protect user identity/session digests, staff factors/recovery codes, private profiles/reports, organization ownership, team consent, frozen rosters, competition results/history, API credentials, webhook signing keys, domain bindings and backups. Adversaries include anonymous callers, ordinary users, malicious captains/organizers, compromised integrations, hostile webhook receivers and custom-domain operators. Database/secret-manager administrators and release operators are privileged trusted actors requiring separate operational controls.

Untrusted browser/HTTP/socket input crosses validated transport into explicit service policies; Prisma transactions cross into authoritative PostgreSQL. Tenant Host resolution crosses only an authenticated ingress and fresh verified database binding. Jobs cross the database outbox into a retrying worker that rechecks authority. SMTP/Google/S3/Cloudflare/webhook receivers cross external-provider boundaries. Logs/backups/CI form separate sensitive operational boundaries. Frontend guards, resource IDs, organization IDs and forwarded headers never prove authority.

## Findings and changes

- Updated Node 22.23.3 to 22.23.4, the current 22.x security patch listed in the [official release index](https://nodejs.org/dist/index.json). Verified the downloaded local archive against official SHA-256 checksums and reran checks with that runtime. See the [October security release](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases). Node 22 remains maintenance LTS; schedule its replacement before support ends.
- Browser/migration test scripts previously lacked the working-database separation guard. All three mutation entry points now use one loopback/PostgreSQL/_test/distinct-database guard, including normalized default ports and loopback aliases, with regression tests. Restore tooling creates and removes only a random fresh disposable destination.
- Explicit validated TRUSTED_PROXIES configuration now supports reviewed ingress addresses. Defaults still trust no proxy; booleans/hop counts and /0 are rejected. Network restrictions and an ingress that overwrites forwarding headers are mandatory. This does not create distributed IP throttling.
- API shutdown now stops accepting connections before draining jobs. The separately compiled worker now has bounded shutdown and safe fixed startup-failure logging.
- Reviewed the single production `$queryRawUnsafe` adapter in notifications/delivery.ts: SQL comes from pg-boss, with values passed separately as parameters. No request-controlled SQL text is passed there. The focused SAST exception is confined to that file; interpolation detection still applies everywhere. Do not reuse this adapter for application-supplied SQL strings.
- Gitleaks initially identified a prose phrase in database-schema.md as a generic key. It was a documentation false positive; wording was clarified without suppressing the rule. No credential rotation was indicated by that finding. Whole-ref history scanning encountered an existing malformed local Git ref; the reachable HEAD history was scanned separately. Remote CI scans a clean full checkout; arbitrary orphaned/local invalid refs are not qualified.

## Residual launch risks

Blocking: no staging provider/HTTPS ingress qualification; no locally executed Docker build/image vulnerability scan; no live SMTP/Google/S3/Cloudflare checks; no cloud backup/key/object restoration; no actual monitoring/alert/on-call verification; no representative multi-instance soak/capacity results; no independent security assessment or jurisdiction/asset-rights review. Authentication SMTP is bounded immediate delivery, so interrupted verification/recovery mail needs retry; durable tournament notifications use pg-boss. General HTTP IP counters are process-local and require ingress enforcement before scale. Staff encryption-key rotation is an explicit controlled migration, not automatic key replacement. Prototype artwork rights and clearly labelled landing examples require launch-owner review.

No security protection was disabled to obtain passing tests. Test-only adapters and disposable data do not establish live provider correctness. See the release report for exact command outcomes and evidence limits.
