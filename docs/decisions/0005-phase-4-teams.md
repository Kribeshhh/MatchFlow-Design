# ADR 0005 — Player identity, team consent and roster snapshots

Accepted 2026-10-31 for Phase 4. The user explicitly chose editable reusable team membership with frozen tournament snapshots, organizer-approved replacements before registration closes, public basic profiles with optional private history, and S3-compatible integration configured later.

Keep the modular monolith and brand. POST /teams/:id/members intentionally now creates a seven-day invitation, not an active membership. Only the recipient can accept/reject. Existing memberships survive with acceptedAt null rather than fabricated historical consent. Captain self-membership and new invitation acceptance record consent time. Managers cannot promote themselves, change another manager, remove captain or transfer ownership. Transfer requires recent authentication by captain and recipient, accepted membership, a 24-hour offer and transactional revalidation. Archive retains records and is blocked while active unfinished entries remain.

Reusable team membership, manager/substitute status and captain ownership may change while tournaments run. Registration stores accepted starters (captain included at submission), excluding substitutes. Only an explicit roster-change request plus organizer approval can replace a snapshot before registration closes and before bracket generation. Approval repeats eligibility/duplicate checks and rejects stale membership. Requests do not reserve extra player slots. Finished/locked event snapshots remain unchanged by team mutations. Games cannot change once team entry history exists. Existing manual registration remains organizer-authorized and cannot create memberships or arbitrary player snapshots.

New accounts default to public basics; profile owners can hide the entire profile, history/statistics or memberships. Existing accounts remain private because their display names/bios were previously self-only. Published tournament rosters/results remain visible independently of profile controls. Deleted identities and pending roster proposals are scrubbed/cancelled.

Use Sharp to check actual PNG/JPEG/WebP content, reject animation, enforce 2 MB/16 MP input bounds and re-encode to at most 512×512 WebP without metadata. Only the server creates storage keys. AWS SDK v3 provides the S3-compatible adapter. A private bucket is accessed exclusively by the API, which checks current profile visibility/asset linkage on each read. Team logos are public branding. Storage credentials/provider are deferred by the user; absent integration is explicitly unavailable. No local fallback or simulated production upload. Old remote logo URLs are removed without fetching them. Run cleanup for unreferenced assets older than 24 hours; originals are never stored.

Integration tests use isolated storage adapters and the unit suite exercises actual signed SDK requests against a loopback fixture. Neither is a live provider qualification. Staging provider permissions/encryption/backup policy, retention and load/security/accessibility checks remain launch gates.
