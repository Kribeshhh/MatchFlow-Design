## Confirmed probe scenarios

Used newly generated test identities/passwords in the isolated test database, not real users. Created two teams and an event, submitted pending entries, read a player's dashboard, then approved/generated/completed a two-team bracket. After completion, replaced a team member and compared old/new dashboards and public detail. Observed F02 and all F03 behaviors. Separate schema probe accepted reversed subsecond dates; Supertest oversize JSON request returned 500. These probes are audit evidence, not committed regression coverage; the follow-up phase must add durable tests.

## Positive findings worth preserving

Server-side ownership/role checks, salted scrypt, hashed opaque sessions, controlled error bodies, strict body validation, foreign/unique keys and serializable competition writes are substantive implementation, not UI placeholders. Tests exercise a real PostgreSQL lifecycle and concurrent final-capacity allocation. Registration snapshots themselves remain stored; the history defect is in read/query projections. The single-elimination engine is reusable, but game branding alone does not supply other scoring rules.

## Source-only gaps and unverified assumptions

Missing account recovery/verification, distributed limits/proxy policy, explicit private cache policy, normalized response contracts, audit logging and operational safety are documented in the security/deployment guides. No exploit against deployed infrastructure was attempted. No current remote deployment or browser modal layout was verified. No evidence establishes that the frontend-only prototype host is the actual production API deployment.

## Phase 1 disposition

F01 resolved by clean installation and build verification. F02/F03/F04/F05 fixed with regression coverage. F06 dependency updates report zero known advisories at verification time. F07 removes embedded/logged seed passwords and restricts local seed targets; pre-existing demo account access still needs deployment review. F10 adds inferred response types, runtime parsing and bounded requests. F11 gains lint/format/type/test/build/CI and local health/log/shutdown foundations; production restore/monitoring/deployment remain open. F12 account/session creation is atomic; cancellation/recovery/correction workflows remain deferred. F08 landing prototype claims and F09 membership/organizer consent policy are unchanged product work.
